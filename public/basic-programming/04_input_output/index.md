<InfoCard title="📘 Core Concept: What is I/O Communication?">
Input & Output (I/O) is how a program communicates with human users—reading data entered via keyboard (Input) and displaying results on screen (Output).
</InfoCard>

<TipCard title="💡 Key I/O Operations & Casting">
1. **Console Output (`print`)**: Displays text strings and variable values to stdout.
2. **User Input (`input`)**: Pauses program execution to read user keystrokes as a text string.
3. **Type Casting**: Converts text input using `int()` or `float()` before performing math.
4. **Formatted Output**: Uses f-strings (`f"Hello {name}"`) to cleanly embed variables into display text.
</TipCard>

<KeyTakeaways>
1. `input()` always returns data as a text string by default.
2. Cast input to `int()` or `float()` whenever numerical calculations are required.
3. F-strings (`f"{variable}"`) provide clean, readable string formatting in modern code.
</KeyTakeaways>

## 💡 Quick Engineering Notes & Pitfalls

<SectionGuideCard sectionTitle="Quick Engineering Notes & Pitfalls Guide" motto="Review production best practices, performance optimization tips, and critical pitfall warnings." whatItDoes="Summarizes key engineering takeaways including Core Concept Overview, Pro Engineering Tips, and Common Pitfall Warnings." clickInstructions="Read through the InfoCard, TipCard, and WarningCard keynotes to prevent edge-case bugs and memory leaks in production code." badge="Summary Notes" />

<InfoCard title="Core Concept Overview">
Input/Output operations stream data between programs, memory buffers, user consoles, and hardware devices.
</InfoCard>

<TipCard title="Pro Engineering Tip">
Use `sys.stdout.flush()` or `flush=True` when outputting real-time CLI progress bars to force instantaneous buffer updates.
</TipCard>

<WarningCard title="Common Pitfall Warning">
Always type-cast `input()` string outputs before performing arithmetic operations (`int(input())`) to avoid TypeError crashes.
</WarningCard>
