<InfoCard title="📘 Core Concept: What is a Function?">
A function is a reusable block of code designed to perform a specific task. You write the code once, give it a name, and call it anywhere in your program whenever needed.
</InfoCard>

<TipCard title="💡 Function Anatomy & Principles">
1. **Definition (`def`)**: Declares a new function with a custom name and optional parameters.
2. **Parameters & Arguments**: Input variables passed into a function to process dynamic data.
3. **Return Statement (`return`)**: Sends computed output values back to the calling code location.
4. **DRY Principle (Don't Repeat Yourself)**: Modular functions keep code organized and maintainable.
</TipCard>

<KeyTakeaways>
1. Functions organize code into clean, testable, and reusable building blocks.
2. Parameters receive dynamic inputs; `return` sends calculated outputs back to the caller.
3. Variables declared inside a function exist only within that function's local scope.
</KeyTakeaways>

## 💡 Quick Engineering Notes & Pitfalls

<SectionGuideCard sectionTitle="Quick Engineering Notes & Pitfalls Guide" motto="Review production best practices, performance optimization tips, and critical pitfall warnings." whatItDoes="Summarizes key engineering takeaways including Core Concept Overview, Pro Engineering Tips, and Common Pitfall Warnings." clickInstructions="Read through the InfoCard, TipCard, and WarningCard keynotes to prevent edge-case bugs and memory leaks in production code." badge="Summary Notes" />

<InfoCard title="Core Concept Overview">
Functions provide code encapsulation, reusability, and clean scope abstraction across software modules.
</InfoCard>

<TipCard title="Pro Engineering Tip">
Never use mutable default arguments like lists or dictionaries inside function definitions (`def f(a=[])`).
</TipCard>

<WarningCard title="Common Pitfall Warning">
Ensure recursive functions have well-defined base cases to avoid StackOverflow and RecursionError crashes.
</WarningCard>
